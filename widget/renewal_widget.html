What actually moves this estimate

Measured properly: the average effect of moving one field across its typical range, computed across every lease in the training data (not just one hypothetical "typical" tenant). Most other fields (screening, late payments) move it 3 points or less.

  • Start month+13pt
  • Unit size+12pt
  • Resolved rate (higher ↑)+7pt
  • Work orders (more ↓)−6pt
  • Term (longer ↓)−6pt
  • Floor (higher ↓)−5pt

Unit size is the one addition here with no missing-data caveats at all — it's joined by unit number rather than tenant name, so it's fully observed for 100% of leases. Start month (seasonality) is the strongest signal and has held up unchanged through every correction made while building this model (see the notebook). Floor's swing is measured on a few dozen leases per floor, so treat it as suggestive rather than conclusive. Rent's effect is small (a couple of points) and not shown above.

About this model. Trained on a single anonymized property's lease records. Rent-roll and survey history only cover tenants who are currently active or who left a survey, so those fields are often blank — the model falls back to the training-set median automatically. Two fields that looked highly predictive (previous rent, unit transfer) were deliberately excluded because they're only recorded after a renewal happens. A "resident-requested work orders" field was removed entirely (always 0 in this data), and bedrooms/bathrooms were tested and dropped too — a trained model never split on either one, since unit size already captures the same information. Past-due balance is sensitive right around its typical value — leave it blank rather than guessing a round number unless you have the exact figure.

Anonymization. All tenant, applicant, staff, and vendor names were replaced with placeholder identities before this model was ever trained, and unit type names were replaced with generic labels. See data/README.md in this repository for exactly how, and the notebook for the full modeling history (including two data-leakage bugs and an overfitting problem that were found and fixed along the way).
